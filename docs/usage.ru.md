## 1. Первый вход

После установки откройте консоль администратора:

- Установка в один клик / Docker: `http://localhost`
- Локальная разработка: `http://localhost:8789`

Войдите с именем пользователя и паролем администратора, заданными в мастере установки. После входа вы попадёте на панель управления с 8 карточками метрик KPI (общие расходы, показы, клики, конверсии, CTR, CVR, средний CPC, средний CPA), линейным графиком дневного тренда расходов, столбчатой диаграммой сравнения платформ и TOP-10 кампаниями.

Смена пароля или данных учётной записи: Управление системой → Управление пользователями.

## 2. Авторизация платформ

Система поддерживает **16 отечественных + 13 международных платформ**, все авторизуются через « Управление аккаунтами → Привязать аккаунт ».

### Платформы OAuth2 (большинство)

1. Выберите целевую платформу на странице « Привязать аккаунт » и нажмите « Авторизовать »
2. Браузер перенаправляется на страницу входа платформы; войдите и одобрите доступ
3. После обратного вызова система автоматически сохраняет токен доступа

Авторизованные платформы появляются в списке аккаунтов. Просроченные токены автоматически обновляются задачей `TokenRefreshTask` (в 55-ю минуту каждого часа) — ручное вмешательство не требуется.

### Платформы с API-ключом

Платформы Qihoo360, Sogou и Umeng используют аутентификацию по API-ключу: вручную введите API-ключ (и параметры подписи) на странице « Привязать аккаунт », сохраните — и синхронизация начнётся.

> 16 отечественных платформ: Juliang (Ocean Engine), Baidu Marketing, Taobao/Alimama, Tencent Ads, Kuaishou, Xiaohongshu, Weibo, Bilibili, Youku Ads, Meituan Ads, Zhihu Ads, Qihoo360, Sogou, Umeng, JD, Pinduoduo Ads
>
> 13 международных платформ: Google Ads, YouTube Ads, Meta Ads, TikTok Ads, LinkedIn Ads, Snapchat Ads, Pinterest Ads, Twitter/X Ads, Amazon Ads, The Trade Desk, Spotify Ads, Twitch Ads, Netflix Ads

## 3. Привязка аккаунтов и загрузка в библиотеку креативов

### Управление аккаунтами

После авторизации платформы аккаунты появляются в списке « Управление аккаунтами ». Каждый аккаунт независимо управляет участием в синхронизации (`sync_enabled`). Рекламная иерархия трёхуровневая: Кампания → Группа объявлений → Креатив.

### Библиотека креативов

« Библиотека креативов » поддерживает загрузку изображений/видео с просмотром в виде галереи для использования в креативах. Загруженные ресурсы могут опционально использовать CDN-хранилище (см. ниже).

### Настройка провайдеров CDN-хранилища

В системе есть встроенная абстракция хранилища с несколькими драйверами; одновременно можно настроить несколько провайдеров:

| Драйвер | Описание |
|---------|----------|
| Локальное хранилище | Драйвер по умолчанию, хранит на диске сервера |
| Alibaba Cloud OSS | AlibabaOssStorage |
| Tencent Cloud COS | TencentCosStorage |
| S3-совместимый | S3CompatibleStorage (совместим с AWS S3, Qiniu Cloud, MinIO и др.) |

Добавьте провайдера на странице « Провайдер CDN » и заполните соответствующие ключи/параметры региона — он станет активным.

### Предподписанная загрузка и очистка кэша

- **Предподписанная загрузка**: сервер выдаёт ограниченный по времени предподписанный URL (PUT OSS/S3) для каждой загрузки; браузер или мобильные клиенты загружают файлы напрямую в объектное хранилище, минуя сервер приложения — меньше трафика и нагрузки
- **Очистка кэша**: после обновления или удаления ресурса можно запустить очистку кэша CDN, чтобы клиенты всегда получали актуальный контент

## 4. Синхронизация данных

Синхронизация управляется 6 запланированными задачами (планируются внутри процесса плагином crontab webman — внешний crontab не требуется):

| Задача | Частота | Ответственность |
|--------|---------|-----------------|
| RetrySyncTask | Каждые 3 минуты | Повтор последней неудачной синхронизации |
| AlertCheckTask | Каждые 5 минут | Оценка правил оповещений |
| DataSyncTask | Каждые 10 минут | Синхронизация кампаний/групп/креативов и отчётов (за 2 дня, 9 метрик) |
| BidCheckTask | Каждые 10 минут | Проверка правил автоставок |
| BudgetCheckTask | Каждые 15 минут | Проверки предупреждений о бюджете |
| TokenRefreshTask | 55-я минута каждого часа | Обновление просроченных токенов платформ |

Конфигурация задач находится в `service/plugin/ads-task/config/cron.php`; частоту можно изменить там же. Статус синхронизации виден на странице « Синхронизация данных »; переключатели по аккаунтам — в « Управлении аккаунтами ».

## 5. Анализ отчётов

### Панель управления

8 карточек метрик KPI + линейный график дневного тренда + столбчатая диаграмма сравнения платформ + TOP-10 кампаний, с фильтром диапазона дат и экспортом PDF/Excel в один клик.

### Пользовательские отчёты

- **Измерения**: date, platform, campaign
- **Метрики**: cost, impressions, clicks, conversions, ctr, cvr, cpc, cpm, roi
- Поддерживаются комбинированные запросы по измерениям и сортировка

### Атрибуционный анализ

Встроенный кроссплатформенный атрибуционный движок поддерживает **5 моделей атрибуции**: first_touch, last_touch, linear, time_decay, position_based, с окном ретроспективы 30 дней. На странице « Атрибуционный анализ » выберите модель и диапазон дат, чтобы увидеть вклад каждого канала.

### Календарь кампаний

« Календарь кампаний » отображает график показа каждой кампании в виде календаря для быстрого обзора ежедневного ритма показов.

### Экспорт

Отчёты поддерживают три формата экспорта:

- **CSV** (UTF-8 BOM, открывается в Excel без искажения символов)
- **Excel** (HTML .xls)
- **PDF** (HTML-макет для печати)

## 6. Оповещения и уведомления

### Правила оповещений

Создавайте правила на странице « Правила оповещений »: выберите отслеживаемый объект (бюджет/расходы/показы/клики и т.д.), порог и способ сравнения, область действия и каналы уведомлений. Включённые правила оцениваются задачей `AlertCheckTask` каждые 5 минут и срабатывают при совпадении.

### Каналы уведомлений

| Канал | Описание |
|-------|----------|
| Web | Уведомления в приложении, видны в « Центре уведомлений » |
| Email | Отправка по электронной почте (SMTP, с запасным `mail()`); настройте адреса получателей в правиле оповещения |
| SMS | Отправка по SMS |
| Webhook | POST JSON на настроенный URL обратного вызова; интеграция с WeCom/DingTalk/Feishu и др. |

История оповещений видна на странице « Журналы оповещений ».

## 8. Мультитенантность

В системе есть встроенный мультитенантный плагин (ads-tenant):

- **Идентификация тенанта**: middleware `TenantIdentify` определяет текущего тенанта для каждого запроса
- **Изоляция данных**: два режима — общая база данных с изоляцией по `tenant_id` или отдельная база данных на тенанта (`db_type`)
- **Управление квотами**: `QuotaService` проверяет квоты тенантов (количество аккаунтов, ресурсов и т.д.); запросы сверх квоты отклоняются
